Techniques to recover from fault

1. Retries
2. Rate Limiting 	- Controls the number of requests the microservice can handle within a time frame. Prevents overload.
3. Bulheads		 	- Isolating different parts of application, so issue in 1 component doesnt affect other components.
4. Circuit Breaker	- Monitor Health of microservice, When request arrives at the faulty microservice, its redirected to fallback service or fallback response is sent back.
5. Fallbacks		- Alternate mechnisms which is invoked if primary service is failed.
6. Timeout 			- If Reponse is not sent within specified time, then user can take desired action, like retry, refresh.

------------------ Retry Pattern --------------------------
Retries are used for temporary failures like bad network, service overload. Not used for permanent failures ex: DB is down.
Retry Mechanism at method level
1. Add @Retry at method level
           int attempt = 0;
           @Retry(name="productService", fallbackMethod = "addToCartFallBackMechanism") // this name is same as in configuration file.
           public boolean addToCart(String userId, CartItemRequest cartItemRequest) {
           }

2. Add   properties in order-microservice.yml
        retry:
           instances:
             retryBreaker:
               maxAttempts: 5
               waitDuration: 5s

3. Shut down product-microservice and call /addToCart

------------------ Rate Limiting --------------------------
Its a technique for limiting network traffic, stops overloading the network. Prevents too many requests buzzing the service.
Its sets the limit , as how many request the service can take

1. Create a /message endpoint in order-mircoservice. -> MessageController.Java
2. Using jmeter hit this end point multiple times -
3. In order-service.yml
     ratelimiter:
        instances:
          rateBreaker:
            timeout-duration: 0
            limit-refresh-period: 4s # Counter period time, means in 4seconds only 2 calls are allowed.
            limit-for-period: 2

 4. Check once MessageController.Java
 5. Set 10 threads to 10 in JMeter and run it.
 6. First 2 requests get us "All is Well", From 3rd request we get response from call back.
